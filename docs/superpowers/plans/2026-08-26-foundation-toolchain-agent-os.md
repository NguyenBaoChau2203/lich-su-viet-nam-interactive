# Foundation Toolchain & Agent OS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create a reproducible Next.js foundation plus one canonical Agent OS that Codex, Antigravity, and OpenCode can consume without duplicating project architecture or silently bypassing safety/quality rules.

**Architecture:** The application shell is intentionally neutral and design-independent. Project law, canonical roles, project-local skills, and machine-checkable guard policies live in shared repository files; each coding harness gets a thin adapter generated or wired to those shared definitions. Heavy product/domain work, Supabase schema work, and map/timeline/3D contracts are separate follow-up plans.

**Tech Stack:** Node.js 24, pnpm 11, Next.js 16.3.2, React 19.2.8, TypeScript, Tailwind CSS 4, ESLint, Prettier, Vitest, Playwright, OpenCode plugin API, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-26-foundation-agent-os-design.md`

## Global Constraints

- Product/UI language is Vietnamese.
- Technical documentation is Vietnamese by default; English is acceptable for code identifiers, API names, and upstream references.
- No final brand identity, final homepage design, production historical dataset, production Supabase credential, irreversible production migration, final motion choreography, or paid service may be introduced in this plan.
- 3D/motion is not implemented in this plan; only later plans may add those runtime dependencies.
- No real secret may be committed. `.env.example` contains names/placeholders only.
- Human instructions > approved specs/ADRs > root `AGENTS.md` > project role/skill instructions > pinned upstream skills > harness defaults.
- Upstream skill baselines stay pinned to the commits already approved in the spec.
- OpenCode V2 plugin API is beta; keep its adapter minimal and isolated.
- Codex project hooks are not assumed. Machine-enforced command hooks are added only where the current harness has a documented hook API; Codex still receives the same policy through `AGENTS.md` and verification scripts.
- Empty directories are not committed merely to mirror the target tree.

- [ ] **Step 4: Wire Antigravity documented hooks**

`.agents/hooks.json` uses a `PreToolUse` matcher for `run_command` and executes:

```text

```

The adapter reads hook JSON from stdin, extracts `toolCall.args.CommandLine`, calls `classifyCommand`, and returns an Antigravity-compatible allow/deny JSON decision. It must fail closed for malformed destructive-looking command input and fail open for unrelated non-command tools because the matcher already scopes it.

- [ ] **Step 5: Wire the isolated OpenCode V2 plugin**

Do not add session/model transforms.

Because the OpenCode V2 plugin API is beta, keep all OpenCode-specific code in this one file and verify loading with the installed OpenCode version during execution.

- [ ] **Step 6: Add repository secret scan**

